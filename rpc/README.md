# rpc/

Стримы (пайплайны) `redpanda-connect` для сервиса `dwh-rp-connect`
(см. `compose/redpanda/docker-compose.yaml`).

## Как сюда попадают файлы

Стримы пишутся не в этом репозитории, а в отдельных внешних проектах
(каждый — в своей папке `dwh/rpc/`).

Внешние проекты деплоятся на тот же сервер, что и `dwh`. После своего
обычного `git reset --hard` их `deploy.yaml` дополнительно копирует
стримы локальным `rsync` в этот проект:

```bash
rsync -a --delete dwh/rpc/ /media/data/projects/dwh/rpc/<project>/
```

То есть при каждом push во внешний проект его стримы автоматически
обновляются здесь, в соответствующей подпапке `rpc/<project>/`.

## Почему эти папки пустые в git

Подпапки `rpc/<project>/` — не источник правды, а место, куда внешние
деплои кладут файлы. Их содержимое в `.gitignore` (кроме `.gitkeep`,
чтобы папки вообще существовали в репозитории). Локально (вне сервера)
эти папки будут пустыми, пока рядом руками не положить туда файлы или
не подключить их иначе.

## Как это подхватывает redpanda-connect

`dwh-rp-connect` монтирует одну из таких папок в `/streams`
(относительно `compose/redpanda/docker-compose.yaml`) и запускается
с флагом `-w` (watch) — при появлении/изменении/удалении файлов
стримов пайплайны перезагружаются на лету, без рестарта контейнера.

## Если добавляется новый проект со стримами

1. В новом проекте — свой `deploy.yaml` со связкой `git reset --hard` +
   `rsync` по аналогии с уже подключёнными проектами, целевая папка —
   `/media/data/projects/dwh/rpc/<project>/`.
2. Здесь — создать `rpc/<project>/.gitkeep` и добавить
   `rpc/<project>/*` (с исключением `.gitkeep`) в `.gitignore`.
3. Добавить мониторинг в `dwh-rp-connect`, если один общий `/streams`
   не покрывает случай (сейчас смонтирована только одна подпапка).
